## 2024-06-12 - Prevent DOM XSS in Webpack Dev Server and Build Templates
**Vulnerability:** The build configuration (`webpack.config.js`) used the `HtmlWebpackPlugin` to dynamically generate `index.html`. It extracted a `widgetName` parameter from the URL's search string and then unsafely appended it to the DOM using `document.body.innerHTML +=` if undefined, and more importantly it injected an unvalidated parameter directly into a `<script src="..."></script>` tag, creating a clear DOM-based Cross-Site Scripting (XSS) vulnerability. An attacker could craft a URL with a malicious `widgetName` parameter to execute arbitrary JavaScript within the plugin's origin context.
**Learning:** Build templates that dynamically construct HTML based on URL query parameters are susceptible to DOM XSS. Client-side routing and widget loading mechanisms should never implicitly trust query parameters without validation, especially when appending to the DOM or constructing `<script>` sources.
**Prevention:**
1. Always validate dynamic script sources or dynamically included partials against a strict, build-time generated allowlist of known valid identifiers (e.g., extracting valid widget names from Webpack entry configurations).
2. Use `document.body.textContent` or `document.createElement` to safely update the DOM instead of assigning to `innerHTML` when handling user-controllable input or fallback error messages.
