## 2024-05-18 - Prevent DOM-based XSS and Domain Spoofing in Webpack Config
**Vulnerability:** The dynamic script generation in the `HtmlWebpackPlugin` template was vulnerable to DOM-based XSS. Unvalidated input from the `widgetName` query parameter was directly injected into the DOM as part of a `<script>` tag. Additionally, error messages were rendered using `.innerHTML`, increasing the risk. Furthermore, the Webpack `devServer` CORS origin validation checked if `origin` strings simply started with `http://localhost:`, allowing a bypass through domain spoofing (e.g. `http://localhost.attacker.com`).
**Learning:** Build-time configuration files often handle sensitive input directly from the browser's execution context. Any query parameters must be rigorously sanitized and validated against an allowlist before injection. Using the `URL` API is critical for safely parsing and validating origins because string prefix matches can be easily spoofed.
**Prevention:** Always validate dynamic parameters against a predefined allowlist (extracted from glob files). Use safe DOM properties like `textContent` over `innerHTML`. Always parse origins using the built-in `URL` API to strictly match hostnames (e.g., checking `url.hostname === 'localhost'`) instead of relying on string methods like `.startsWith()`.
