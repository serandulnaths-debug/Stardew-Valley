## 2024-05-28 - Fix DOM-based XSS and CORS Spoofing in Webpack
**Vulnerability:** Found a DOM-based XSS vulnerability in `webpack.config.js` via unvalidated `widgetName` query parameters rendered using `innerHTML`, and a CORS domain spoofing vulnerability in `webpack-dev-server` headers due to an insecure `.startsWith` validation logic.
**Learning:** Build scripts and dev servers often generate dynamic output containing user input directly (e.g. from URLs). Relying solely on `innerHTML` when appending string templates without validating against known values leads to DOM-based XSS, while loose string methods like `.startsWith` for host verification fail to handle subtle spoofing such as `http://localhost.evil.com`.
**Prevention:** Build-time inputs should be explicitly validated against dynamically collected allowlists (like mapping entry points directly) before injection into a runtime script. Always use strict `textContent` for text rendering to inherently neutralize XSS, and strictly parse domains using the `URL` API when verifying origins.
