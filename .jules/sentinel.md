## 2024-05-19 - [DOM XSS via Unvalidated WidgetName in Webpack Dev Server]
**Vulnerability:** The application used `document.body.innerHTML += ...` to display errors when the `widgetName` query parameter was missing. A missing or maliciously crafted `widgetName` parameter could be leveraged, and more importantly, dynamic module scripts (`<script src=widgetName+"...">`) were created directly from unvalidated user input via `window.location.search`.
**Learning:** Using `innerHTML` for displaying errors based on URL parameters directly leads to DOM-based XSS. Also, dynamically creating a script tag with its `src` derived entirely from an unvalidated query parameter allows an attacker to execute arbitrary module scripts. Webpack's `HtmlWebpackPlugin` was directly serving this unsafe template.
**Prevention:** Always use `textContent` (or `innerText`) instead of `innerHTML` when displaying un-sanitized user input. Implement an allowlist strategy for dynamic resources (like script `src` paths) by cross-referencing user input against valid known keys (e.g., build-time extracted widget names) before rendering the elements.
